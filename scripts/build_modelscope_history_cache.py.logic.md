# build_modelscope_history_cache.py 代码逻辑

## 职责

为 ModelScope Studio 发布包生成所有 WhereFit 城市的 Open-Meteo ERA5 历史天气缓存。

## 输入与输出

- 输入：`data/city_seed.csv` 中的城市坐标、时间范围和发布包缓存目录。
- 输出：默认每个城市一份完整的 ERA5 日尺度 CSV，名称与应用的完整历史缓存读取逻辑一致；也可按五年分块输出。

## 函数与类

| 名称 | 职责 | 关键输入/输出 |
| --- | --- | --- |
| `date_chunks` | 划分五年日期区间 | 起止日期 → 日期分块（分块模式） |
| `fetch_daily` | 请求并验证一个 ERA5 分块 | 城市坐标、日期 → 日尺度字段 |
| `valid_chunk` | 判断已有分块是否可复用 | CSV、日期 → 布尔值 |
| `build_one` | 构建一个城市的完整缓存或分块 | 城市 → 复用/下载计数 |
| `main` | 并发调度选定城市批次 | 参数 → 成功或失败状态 |

## 数据流与主要步骤

1. 读取全部城市坐标；默认每城只请求一个完整日期范围，必要时可选按五年分块。`--city-offset` 和 `--city-limit` 可将断点续传拆为小批次，已有有效文件仍会复用。
2. 复用完整的既有 ERA5 文件；缺失时从 Open-Meteo Archive API 下载，并遵守服务端的限流等待时间。
3. 验证字段和日数后原子写入发布包的缓存目录。
4. 输出每个城市的复用、下载和失败情况。

## 依赖、配置与运行方式

- 仅使用 Python 标准库；默认单并发、请求间隔一秒，并遵守公开 API 返回的限流等待时间。
- 示例：`python scripts/build_modelscope_history_cache.py`；小批次续传可用 `--city-offset 10 --city-limit 5`。

## 假设、边界与注意事项

- Open-Meteo 历史数据通常滞后约十天，脚本默认避开最近十天。
- 默认完整缓存将直接命中应用的历史读取路径；实时预报、AQI、灾害和极光仍保持刷新逻辑。
