# build_modelscope_history_cache_batch.py 代码逻辑

## 职责

通过 Open-Meteo 官方支持的多坐标查询，为尚未完整预置的城市分批生成 ERA5 日尺度历史缓存。

## 输入与输出

- 输入：城市种子表、2000 年至 API 可用结束日的 ERA5 日尺度字段。
- 输出：发布包历史缓存目录下每城市一份完整 CSV；已有完整文件不覆盖。
- 可选参数：`--end-date YYYY-MM-DD` 固定完整缓存的截止日期，用于跨日恢复时复用已保存的断点，而非重新下载此前已完成的城市。

## 数据流

1. 读入所有城市并过滤已验证的完整缓存。
2. 将剩余城市分成每批最多 5 个坐标。上游对 10 城完整历史响应明确提示数据量过大，5 城使单次响应保持在更保守的范围。
3. 每批请求完成后，先验证该批全部响应的字段与日期数量；只对通过验证的整批分别原子写入城市 CSV。
4. 两批之间等待 30 秒，以降低连续请求被限流的风险；已成功的批次可在下次运行时复用。
5. 若上游返回 HTTP 429，则读取其 `Retry-After`（若无或无效则等待 60 秒）后，最多重试该批 3 次；该批始终在完整验证后才写入。

## 边界

- 使用现有生成器的字段、命名、校验和原子写入函数，不引入新依赖。
- 单次响应较大，超时上限设为五分钟；单批失败时不写入该批的部分结果，先前成功批次保持可用。
- 采用本机现有 Python 版本兼容的配对方式；响应数量在配对前已显式校验，仍可保证一城对应一份响应。
- 未指定截止日期时仍使用 API 最近可用完整日；指定日期必须不早于 2000-01-01。
