# test_product_logic.py 代码逻辑

## 职责

验证本轮全项目审计修复的关键产品口径和页面回归路径。

## 输入与输出

- 输入：种子城市表、合成天气/空气质量数据、Streamlit 测试页面。
- 输出：pytest 断言结果；不保留运行产物。

## 函数与类

| 名称 | 职责 | 关键输入/输出 |
| --- | --- | --- |
| `_preference` | 构造稳定偏好 | 场景、月份 / `UserPreference` |
| `_beijing_row` | 读取固定城市样本 | 无 / 北京数据行 |
| `_valid_forecast` | 构造短期预报 | 城市 / `ForecastSummary` |
| `_location` | 构造海盆选择用城市坐标 | 城市和经纬度 / `Location` |
| `test_*` | 验证时间尺度、fallback、数据质量、供应商契约和 UI | 合成或种子数据 / 测试断言 |

## 数据流与主要步骤

1. 从现有种子表构造确定性评分输入。
2. 用合成短期预报和空气质量验证不同时间尺度不会混用。
3. 验证跨月预报切片、英文月份名称、EONET 边界框/日期字段和 IBTrACS 全球海盆选择。
4. 验证来源覆盖按明确数量展示，不再把启发式完整度显示成置信百分比；英文卡片不得残留中文注意项。
5. 验证预报失败、历史字段缺失、带抓取时间的极光短临缓存边界及灾害证据类型命名。
6. 静态页面接入 POWER 与 ACAG 后，非回退数据组计数和“城市使用历史气候”均应为 3/3；旅行场景历史页明确说明主排名已使用 POWER 基线，且不冒充独立来源数或伪置信百分比。
7. 手动预报查询以四城市屏障证明并发执行且保持结果顺序；过期极光缓存刷新失败时必须退回启发式。
8. 使用 Streamlit `AppTest` 走通默认示例、离线城市比较、语言切换和主题切换，并确认结果标签仍保留。

## 依赖、配置与运行方式

运行 `python -m pytest -q tests/test_product_logic.py`。

## 假设、边界与注意事项

- 页面回归测试使用离线静态比较，避免依赖外部 API。
- 临时极光缓存由 pytest 的 `tmp_path` 管理，不写入项目缓存目录。
