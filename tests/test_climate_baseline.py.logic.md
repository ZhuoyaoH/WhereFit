# test_climate_baseline.py 代码逻辑

## 职责

验证随项目发布的 77 城 NASA POWER / MERRA-2 月度/年度气候基线覆盖、物理合理性、运行时接入、派生字段标记、图表方向和 manifest 可追溯性。

## 输入与输出

- 输入：城市种子表、POWER 两张 CSV、ACAG PM2.5 表和 POWER manifest。
- 输出：无持久产物；通过断言确认静态推荐使用版本化数据。

## 函数与类
| 名称 | 职责 | 关键输入/输出 |
| --- | --- | --- |
| `_sha256` | 计算产物哈希 | 文件 / SHA-256 |
| `_baseline` | 加载并触发完整性校验 | 两张 CSV / 1001 行表 |
| `test_bundled_*` | 校验 77×13 覆盖和固定年份 | 基线表 / 覆盖断言 |
| `test_builder_*` | 校验 POWER 字典响应映射、来源与派生字段 | 单城响应 / 聚合与响应来源 |
| `test_emergency_*` | 校验南半球人工回退相位 | 悉尼种子行 / 1 月与 7 月关系 |
| `test_baseline_seasons_*` | 校验南半球季节与北京冬季 | 典型城市月份 / 温度关系 |
| `test_annual_*` | 校验年度阈值日数与月度求和一致 | 三个城市 / 数值断言 |
| `test_static_*` | 校验 POWER+ACAG 来源、直接湿度与派生标记 | 城市行 / `ClimateMetrics` 与数据质量 |
| `test_charts_*` | 校验图表统一为越高越匹配 | 两城市结果 / Plotly trace |
| `test_climate_manifest_*` | 校验模型、公开访问、公式、行数和文件哈希 | manifest / 来源断言 |

## 数据流与主要步骤
1. 用合成的 POWER 点响应验证参数映射、聚合、派生体感温度和响应哈希。
2. 加载月度和年度表，确认每城 0—12 周期齐全且无逐日缺失聚合痕迹。
3. 用悉尼、墨尔本和北京做不会被人工北半球季节公式满足的代表性检查。
4. 把基线与 ACAG 接入评分，确认气候、湿度、长期空气质量三组均为非回退来源，并明确体感温度和雪日代理为派生字段。
5. 检查雷达和柱状图不使用“安全”措辞且所有可视维度方向一致。
6. 重新计算 CSV 与构建脚本哈希并与 manifest 对照，同时锁定体感温度公式使用 WS10M 日均风而非 WS10M_MAX 最大风。

## 依赖、配置与运行方式

使用 pytest、pandas、Plotly 和项目数据加载/评分模块；不发网络请求。

## 假设、边界与注意事项

- 代表城市检查是数据管线合理性防线，不是对 POWER/MERRA-2 科学准确度的独立验证。
- 哈希测试固定本次版本化产物；重新构建后 manifest 必须同步更新。
